# test/mutations —— 变异清单索引

> **这个文件只回答一个问题：现在该跑哪一个？**
>
> 立档理由（2026-10-01 清理轮）：这个目录里躺着 **34 份**清单、共 **324 条**变异，
> 命名五花八门（`d<步>` / `q<问题号>` / `review-<日期>` / `t<任务><版本>` / `zcode-0928`…），
> **没有任何索引**。于是"这轮改完该复跑哪些"只能靠翻台账 —— 而台账说的是"当时"，不是"现在"。
>
> 每条清单都**只打它那一处**（换了写法就打不穿的判据是假绿），所以它们是本项目
> 「判据到底有没有盯住」的**唯一证据**。别把它们当一次性脚本删掉。

## 怎么跑（三条，缺一不可）

```bash
# ① 本机 shell 注入的 NODE_OPTIONS 会把 err.code 改写成 CODEBUDDY_BROKER_DENY（R39），
#    不带这个前缀 → smoke 基线不绿 → mutate 会**正确地**拒绝开跑，而人极容易读成"项目坏了"。
# ② 并行的两份副本要用 QQBOT_MUTATE_WORK 与 QQBOT_SMOKE_BASE_PORT 错开（工作目录**不能复用**：
#    复用会把工作树回滚，本项目丢过 280 行）。
# ③ 跑变异时**不许编辑被测文件**（还原机制会把它一起回滚）。
NODE_OPTIONS= node scripts/mutate.mjs test/mutations/<本文件>
NODE_OPTIONS= node scripts/mutate.mjs --restore     # 万一进程被杀，用这一条复原
```
