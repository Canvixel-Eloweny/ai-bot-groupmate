动效实验室 · 液态开关

组件本体是 liquid-toggle.js，动效引擎是 motion.js（零依赖的 framer-motion 替身）。每一张卡片回答一个具体问题，并把能调的参数做成旋钮 —— 这不是效果图，是判据的可视化。

最容易漏的是旋钮值（Speed 50 / Stretch 36 这类）—— 只给代码不给旋钮， 出来的是「能跑但参数全死」的东西。

01组件本体：拖它、点它、用键盘操作它

一个位置，两种写法。拖拽时手指直接写，松手时弹簧接管 —— 两者写同一个格子。

点一下 · 拖过去 · Tab 聚焦后按空格
判据 ① 拖尾是弹簧跟随，不是延迟。 后面那颗小液滴是「弹簧追着主液滴此刻的值跑」， 不是「和主液滴同一个目标 + 延迟」。这个区别是整个组件的灵魂： 延迟描述的是点击 —— 液滴迟一步出发，落到主液滴早已离开的地方； 弹簧永远在追当前位置，所以拖得慢两团始终是一个形状，甩得快才在后面拉出细颈。
判据 ② 拉伸要面积守恒。 液滴沿运动方向拉长（scaleX）、垂直方向压扁（scaleY）， 且 scaleY = 1 / scaleX。不守恒就是「鼓起来了 / 变胖了」，一眼假。 动一动 Stretch 旋钮就能看见截面变化。

02同一个视觉，两种底层机制

两边看起来都是「后面拖一个」。左边是延迟，右边是弹簧跟随。 慢拖看两者一样，快甩就分家了 —— 这就是为什么这条判据值得单独占一张卡。 点顶部「自动演示」对比：偶数次是慢拖，奇数次是快甩。

✗ 延迟（跟同一个目标 + transition-delay）
液滴迟一步出发 → 落点是一个主液滴早已离开的位置。快甩时两者脱开。
✓ 弹簧跟随（追主液滴当前值）
永远在追「它此刻在哪」→ 拉伸量恰好等于你的移动速度。
实测 同一次甩动，两组的最大间距（Chromium 逐帧采样）：
实现峰值间距形态
延迟 24.3px 超过液滴直径 36px 的一半 → 两团完全脱开，变成两个孤立的球 + 一段距离
弹簧跟随 12.7px 始终保持重叠 → goo 能拉出细颈，读作一个被抻长的液滴
这组数字不是示意：24.3 > 36/2 意味着中间那段"桥"细到撑不住， goo 滤镜会断成两团。液态感的前提是两团始终重叠，这是硬约束，不是审美偏好。
怎么自己验：点自动演示两次（偶数次= 慢拖，奇数次 = 快甩）。 慢拖时两个实现看起来一样；快甩时左边直接掉队。 这一条不实测很难相信，而实测一次就再也忘不掉。

03三个「看起来能动但其实不对」的反例

这三个都是 Bencho 原作者踩过并修掉的。它们的共同点： 代码能跑、回归全绿、肉眼在快速动作下才暴露问题。

✗ transform 上加 CSS 过渡
每帧写 transform + CSS 过渡 = 对每一帧重新插值。 最后看到的是那条缓动曲线，弹簧被彻底旁路。
✓ 只让颜色过渡
transform 一律不加 transition；只有 background 这类 「没有弹簧在管」的属性才过渡。
✗ 滤镜层上用半透明
feColorMatrix 对 alpha 做阈值 → 半透明填充整个消失。 要调色就 color-mix，不要 opacity。
排错 goo 效果突然不工作，九成是给色块加了 opacity 或换成了 rgba()。滤镜要的是不透明，不是"看起来是那个颜色"。
排错 液滴跑到轨道外面 / 居中跳到中间：忘了写 left: 0。 这些是 inline 元素，left:auto 时静态位置由行盒决定， 而按钮会把文本居中 → 两个 blob 都被推到轨道正中。

04两个拨盘 = 一个弹簧的两个属性

Bounce 是阻尼、Speed 是刚度，两个旋钮都是同一个弹簧的属性， 而不是两条不同的缓动曲线。所以 UI 上不该给用户"曲线"选项。

阻尼比 ζ < 1（欠阻尼）
有过冲、有回弹。控制台里这是错误的位置 —— 开关不该"啪"一下到位。
ζ ≈ 0.87（本项目采用）
仍带一点弹性暗示，而那点暗示就是全部。到 95% 约 16 帧。
判据 ③ 阻尼写死，不给用户"回弹"旋钮。 从死板到活泼的整个范围，区别只在「一个能用的控件」和「一个在表演的控件」之间。 Speed 仍然可调，因为"多快"是个真问题；Bounce 不是。
临界阻尼 c = 2√(km) 是"最快抵达且完全不过冲"的那一档。 本项目 k=170 m=0.9 → 临界 c = 24.7；取 21.5 即 ζ=0.87（欠阻尼一侧一点点）。
参数值决定什么可调吗
stiffness170 − (50−speed)×1.1多快抵达（Speed 拨盘）✅ 用户可调
damping21.5（ζ≈0.87）有没有回弹、手感软硬❌ 写死
mass0.9惯性重量感❌ 写死
除数（速度→拉伸）600拉伸的可见程度❌ 标定值
拉伸上限0.4留给 Stretch 旋钮的余量❌ 标定值

05怎么接进真面板

三行。零构建、零依赖、零服务。

位置加什么注意
index.html 的 <head> <link rel="stylesheet" href="liquid-toggle.css"> 放在 style.css 之后，让组件样式能覆盖令牌默认值
<body> 末尾 <script src="motion.js"> 然后 <script src="liquid-toggle.js"> 顺序不能反：liquid-toggle 启动时要读 window.Motion
app.js 的渲染处 LiquidToggle.create({ speed, stretch, on, onChange }) 把返回句柄存起来；元素移除时必须调 destroy()，否则 rAF 泄漏
纪律 一份语义，一份实现。 弹簧公式只在 motion.js 里存在一次（springStep）。 需要自己控制时钟的组件调它，不要在组件里再抄一份 —— 抄一份就多一个能悄悄对不上的机会，而且两个副本会各自漂移。
关于形态：液态 goo 适合"少量、关键、状态明确"的控件（总开关、模式切换）。 面板里不要整页都液體 —— 密集中文界面靠层级和留白分区， 满屏液态会削弱可读性。style.css 开头那条"安静的仪表盘"主线仍然成立。
方法论来源 bencho.dev「Liquid toggle」， 原配方基于 React + framer-motion。本页为零依赖重实现，参数与手感保持一致。
