## 顶部导航：「灵动岛」三级玻璃（2026-10-02 · 2026-10-03 B29 重排）

一级导航（`.nav1`，8 个功能域）从「通栏色带 + Ant 下划线」改成了**浮在胶囊岛里的一条**。
**B29 起三层全部是液态玻璃，且岛跟随主题**（此前是"两套主题都是纯黑"）。

B29 把二级 tab 栏 `.nav2wrap` **上移**到顶栏正下方、灵动岛**下移**（DOM 顺序）——
三层自上而下：**顶栏（h58·z42）→ 二级 tab 栏（h48·z40）→ 灵动岛带（h76·z41）**，
总玻璃高 182px 与 B28 相同。⚠️ 「上移」的本质是**改 DOM 顺序**：
三层都是 `position: sticky` 且都在正常文档流，文档顺序决定谁在上
（契约 §60⑧N14 钉的就是它；N7/N8 判的是样式里写的 top 与 z-index，**改 DOM 它们不报**）。

```
.topbar      吸顶·z42·白纱 .16·blur 8px
.nav2wrap    吸顶·z40·白纱 .66·blur 8px·**fit-content + 右缘斜角切割**（B30：不再通栏，玻璃只包选项）
  .nav2        横向滚动容器（不是换行，见下）
    .sub × N     页签：默认 / 悬停 / **选中 = 2px 下划线**（B29 从"白底色块"改来）
  （B30：`.page-meta`「即时页 / 点一下立刻生效」已整块删除）
.nav1        吸顶·z41·透明带
  .nav-inner   岛本体 = **玻璃胶囊** + 投影 + 横向滚动容器 + 指示器的定位基准
    .grp × 8   选项：默认 / 悬停 / 选中（描边 + 字重）
    .cnt        计数胶囊（**自己的墨色** `--c-nav-cnt-fg`，不是 inherit）
    .nav-ind    唯一的高亮滑块，位置与宽度由 app.js 每帧写
```

### 三种白纱厚度 —— 三个值是**三种背板的必然结果**，不是随手调的

| 层 | alpha | 背后滚过去的是 | 实测下限 |
|---|---|---|---|
| 顶栏 | `.16` | 浅色页面底 | `.16` 就够 |
| 二级 tab 栏 | **`.66`** | **卡片网格**（含 `--c-accent` 深色按钮 L=0.087） | `.16` → tab 字压那个按钮只剩 **1.88:1**（按钮滚过时字消失）；`.58` 也只有 3.99 ✗；`.66` → 4.84 ✓ |
| 灵动岛 | **`.82`** | 两侧是页面底 + 少量流体（`fit-content` 胶囊） | 胶囊的透光度天然比通栏高 |

### 灵动岛的三态与对比度（B29 改为跟随主题）

| 态 | 浅色（玻璃底 rgb(251,253,254)） | 深色（rgb(11,18,38)） |
|---|---|---|
| 默认 `--c-nav-fg` | **6.60:1** | **6.24:1** |
| 悬停 `--c-nav-fg-hover` | 9.48:1 | 7.09:1 |
| 选中 `--c-nav-fg-on` | **11.04:1** | **18.60:1** |
| 描边 `--c-nav-ring`（指示器 1.5px） | 11.04:1 | 18.60:1 |

⚠️ **不能只改底色**：B29 前 7 个前景色深浅**完全同值**（因为只有一个黑底），
换成浅玻璃后实测全部失效（`fg` 7.04→2.74 ✗ · `on` 21.00→**1.09** ✗ 选中字完全看不见）。
⇒ 底色与 7 个前景色必须**成对**改，而深浅两块都要改。

`verify.mjs` 有**两条**断言（浅/深各一），**共用同一个 probe 函数**（不复制判据逻辑），
且它**真读 computed style 并按 alpha 合成到实测背板**再算 —— 不是"令牌声称的底色"。
（首版只读令牌 ⇒ 成对改成任何过 4.5 的组合就永远绿，它验证的是"令牌自洽"不是"看得见"。）
断言里还带 `on > fg`（默认字须**严格弱于**选中）：首版用
`querySelector('.grp')` 取的恰好是选中项（首次渲染 `S.gi=0`），三个值全同、变成自己和自己比。

### 二级 tab 栏为什么改成横向滚动
B29 上移后它与顶栏**同宽**（通栏 + `padding: 0 var(--s5)`）：
① 通栏里 `flex-wrap: wrap` 换行会在玻璃中间横一道断线；
② 720px 断点下换行会让 `--h-nav2` 漂，而 `.nav1` 的 `top` 正引用它；
③ 灵动岛已用横向滚动解决同类问题 —— **同一页两套溢出策略是本项目反复在清的东西**。
⚠️ 已知取舍：窄屏下选中项可能被切出视野（灵动岛有 `scrollNavTo` 可复用，
但要动 `app.js`，与"灵动岛内部结构不能动"相悖）。点击委托靠 `closest()` 不依赖可见性。

### 动效：从 RareUI 的 GooeyNav 取什么、不取什么

公开实现（React Bits / vue-bits 的 `GooeyNav`）内核是**一个浮层承载高亮**，不是它的滤镜。

- **取**：① 单滑块 ② 弹簧位移（打断不重置速度）③ **速度 → 形变**：横向拉伸、纵向按
  `Motion.areaPreservingScaleX` 压缩（面积守恒，"被抻长"而不是"变胖"）④ ~230ms 收敛的手感
- **不取**：气泡粒子（控制台主线是「安静的仪表盘」）；SVG `feGaussianBlur + feColorMatrix`
  gooey 滤镜 —— 我们的高亮是**描边**，滤镜会先把它糊掉再还原成一坨；且要复制一层 DOM 文本
  才能不糊字（8 项 × 2 层）。收益是"粘连"观感，成本是一份重复 DOM 与两套主题下的对比度复查。
- **零新增依赖**：用本目录已有的 `motion.js`（`window.Motion`）。`package.json` 依然只有 `ws`。

### 四条约束（改了就以"看着像坏了"的形式退化，且**不报错**）

1. **指示器不许被重建**。`renderNav1()` 只摘/插 `.grp`，`.nav-ind` 是 `index.html` 里的静态元素。
   一重建，每次切换就变成"新元素从 0 位置长出来"，滑动感当场消失。
2. **指示器必须在 `.nav-inner` 内部**。窄屏靠这一层横向滚动；挂在外层它会相对视口静止，一滑就错位。
3. **坐标基准是 `offsetLeft`**（相对 `offsetParent` = `.nav-inner`），不是 `getBoundingClientRect()`
   —— 后者含滚动偏移。
4. **岛高 / 选项高 / 指示器高度三者同源**：`--h-nav1` / `--h-nav-item`。触摸区补到 44px 时
   改的是这两个令牌（不是给 `.grp` 单独加 `min-height`），否则白框会比选项矮一截。

### 窄屏策略（不溢出、不换行错位）

- 岛是 `width: fit-content` + `max-width: 1560px`：内容装得下就贴合内容宽，装不下才滚。
- 溢出**只有一种**处理方式：`.nav-inner` 横向滚动 + `.grp { flex: none }`（`flex-wrap` 保持 `nowrap`）。
  **不做换行** —— 8 个功能域名很长，360px 下换行必然断在词中间，那正是要避免的"换行错位"。
- 切换后由 `scrollNavTo()` 手动调 `inner.scrollLeft` 把选中项带进视野。
  **不用 `scrollIntoView`** —— 它会把整页纵向滚一下。
- 断点：≤900px 岛外留白降到 `--s4`；≤720px 岛高 48 / 选项 36、字号降到 `--t-sm`；
  `@media (pointer: coarse)` 岛高 60 / 选项 44。
- 左右内边距 `max(--s5, env(safe-area-inset-*))` —— 刘海/圆角屏上岛不会被切掉。

### 吸顶偏移：由令牌**推导**，不是写死的

`.nav2wrap { top: calc(var(--h-topbar) + var(--h-nav1) + var(--h-nav-pad) * 2) }`。
灵动岛之后"岛高"与"这条带子高"不再相等 —— 用错那个的表现是**二级导航上沿被岛压掉一条**，
而两级导航各自看起来都正常。

> 实测（1440×900）：顶栏 58 · 一级带 76（岛 56 + 上下各 10）· 二级导航吸顶起点 134 = 58+76 ✅

## 怎么跑

**正常用法：点 QQ-BOT-CONTROL 图标。** 它开的就是 `http://127.0.0.1:8788/`（控制台的家）。

手动打开：

```
http://127.0.0.1:8788/                ← 控制台（面板自己发的，同源、自带 token）
http://127.0.0.1:8788/next/           ← 老地址，302 → 根（书签兼容，别存这个）
```

**为什么不需要另起一个小服务**：面板不发 CORS 头，另一个端口打开的页面连 `/api/state`
都取不到、写请求也拿不到 token。所以"能点进去"这件事唯一正确的接法就是**让面板自己发**。
改任何资产都**不需要重启面板** —— 每次请求从磁盘读，改完刷新即可。

自检：

```bash
node panel/next/verify.mjs      # 28 条断言 + 3 张截图 → /tmp/next-verify/
                                # 默认验 http://127.0.0.1:8788/（控制台的家）
                                # 其中包含**真写一次**（POST /api/logs/clear，零副作用）
                                # 换宽度复跑：--width 390 / --out /tmp/next-narrow
```

## 怎么加/删

**加一个页面**：在某个域的 `subs` 里插一项。

```js
{ id: 'my-page', label: '我的页', title: '我的页标题', desc: '一句话说明。',
  draft: true,                       // true → 底部出现「保存并生效」；false/省略 → 点一下立刻生效
  cards: [ { id: 'c1', title: '卡片标题', span: 6, ctrls: [ /* … */ ] } ] }
```

**加一个控件**（存进 `custom` 的，走草稿）：

```js
{ t: 'switch', id: 'x.on', label: '开关名', bind: 'crossSend.enabled', hint: '这里是说明。' }
```

**加一个立即生效的控件**（自己声明打到哪个接口）：

```js
{ t: 'switch', id: 'dbg', label: '详细日志', read: (s) => s.debugLog,
  save: (v) => ({ url: '/api/debug', body: { on: v } }) }
```

**删**：把那一项删掉即可，不需要动任何别的地方。

### 三条会自动报错的纪律（都写进了代码）

1. `RENDER` 表里没有的控件类型 → 页面上**当场画红框**，不静默跳过（静默跳过 = 少一个控件）。
2. 页面上每个 `data-a` 动作必须有处理者（`ACTIONS` 或 `INLINE_ACTIONS`）→ 否则 `console.error`，
   自检脚本会把它算成失败。
3. 静态标记里出现 `data-act` 这类别的属性名 → 同样报错（已实测踩过：顶栏四个按钮全静默失效）。
