# QQ 官方机器人通道（Official Bot Channel）

> 新增于 2026-11-06。本文件说明**第二条消息通道**是什么、怎么配、能做什么、做不到什么。
> 现有 NapCat（OneBot v11）通道的行为完全不变。

## 1. 这是什么

机器人由两部分组成：**大脑**（人设、聚批、档位、模型、记忆、插件）和**嘴**（收发消息的通道）。
本项目原来只有一条嘴 —— NapCat 之类的第三方协议端（注入官方 QQ 客户端）。
现在多了一条官方嘴：**QQ 开放平台机器人**（AppID + AppSecret → 事件网关 WebSocket + OpenAPI REST）。

两条通道**同一时间只跑一条**，由配置里的 `channel.mode` 决定：

| 值 | 含义 | 需要装什么 |
|---|---|---|
| `napcat`（默认） | NapCat / OneBot v11 | 与以前完全一样（扫码登录、3001 端口那一套） |
| `official` | QQ 官方机器人 | 不需要 NapCat，不需要 Docker，只出站到 `api.bot.qq.com` |

> 默认是 **NapCat**（2026-11-06 维护者指定）：协议端一登录就能说话；官方通道在填好
> AppID + AppSecret 之前不会出声，所以不该让新装第一眼就停在"缺凭据"。新装与旧配置都回落 NapCat。

切换通道要**重启机器人**（面板会提示）。这不是实现偷懒：出口在启动时一次性决定，
运行期热切换会让两条链路同时持有同一个会话，最坏表现是"同一条群消息被回两次"。

## 2. 怎么开通官方通道

1. 到 QQ 开放平台（`q.qq.com`）创建机器人应用，拿到 **AppID** 与 **AppSecret**。
   注意：控制台里叫 AppSecret，官方取 token 的请求体字段叫 `clientSecret`，是同一个东西。
2. 把机器人**拉进群**，群主在手机 QQ 的群设置里打开两个开关：
   - **接收所有消息**：不开的话，机器人只收得到"@ 它"的消息，收不到群友普通发言；
   - **允许主动发言**：不开的话，机器人不能主动在群里说话。
3. 打开控制台「运行 → 切换协议端」，在「接入通道」卡里选「QQ 官方机器人」，填 AppID / AppSecret，保存。面板会立刻刷新出官方态；点「立即重启生效」（没在跑则是「立即启动生效」）加载新通道。
4. 在群里 @ 机器人一次。它会在「群与身份绑定」里以"待绑定群"出现，填上真实群号完成绑定。
5. 把主人自己的账号也绑上（同一页「设为主人」），否则私聊、叫醒、主人通知都不认你。

AppID 可以直接填；AppSecret 建议走环境变量引用：`"appSecret": "env:QQBOT_OFFICIAL_SECRET"`。
凭据只留在本机 `config.json`（0600），面板与日志只回掩码，不会把它们发出去。

## 3. 身份：openid 而不是 QQ 号

官方 API 不暴露 QQ 号，群与人都是 **openid**（32 位十六进制串），而且：

- 官方**不提供** openid → QQ 号的查询接口（隐私设计）；
- 同一个人在不同群里是**不同的** member_openid；
- 同一个人在不同机器人应用下也是不同的 openid。

本项目的处理方式是：**openid 原样作为内部身份**，不做任何"哈希截短 + 数字前缀"的假 QQ 号。
假号看着省事，但它把"陌生人能不能撞进权限链"变成了概率问题 —— 而白名单、主人、私聊记忆
都走这条链。需要延续旧数据时，用面板的**人工绑定**：

- **群绑定**：`group_openid → 真实群号`。绑定后这个群沿用旧的会话键，人格、记忆、白名单都接得上；
- **主人绑定**：把某个 openid 加进 `owner.qq`。只有你明确点过的那一条会生效。

没绑定的群/人一律按 openid 独立工作：能正常聊天，但**不继承**任何旧权限与旧记忆。
名字（昵称）只用于显示，绝不作为身份或权限依据 —— 改名冒充是这类机器人最常见的攻击面。

## 4. 能力矩阵（官方通道）

| 能力 | 状态 | 说明 |
|---|---|---|
| 群聊文字收发 | ✅ | |
| 被 @ 触发 | ✅ | 官方 `GROUP_AT_MESSAGE_CREATE` 是真值证据，不靠正文里的"@名字"文字 |
| 群普通消息（不 @） | ⚠️ | 需要群主逐群打开「接收所有消息」；这个开关**没有 API 可读**，面板只能显示"未知" |
| 私聊收发 | ✅ | |
| 图片 | ✅ | 入站自动进识图链路；出站先上传换 `file_info` 再发 |
| 引用回复 | ✅ | 出站用 `message_reference` |
| 出站 @ 别人 | ❌ | 官方没有 at 段。会降级成正文里的 `@名字`，**不是**真 ping |
| 合并转发（发） | ❌ | 官方无对应端点，明确报错而不是假装成功 |
| 合并转发（收） | ✅ | 入站当场拍平成文本 |
| 历史消息回查 | ❌ | 官方没有历史接口；"引用某条消息再展开"这类动作会明确失败 |
| 群成员 / 好友列表 | ❌ | 相关接口是内邀白名单，普通应用拿不到 |
| 主动发言 | ⚠️ | 受逐群开关 + 每日每群配额限制；平台侧随时可能拒 |
| 被动回复窗口 | ⚠️ | 群聊 5 分钟内、同一条消息最多 5 次；超了就是明确失败 |
| 语音 / 视频 / 文件 | ⚠️ | 入站能收到并标注；出站本批未接 |
| 拍一拍 / 禁言事件 | ❌ | 官方没有对应事件 |
| 扫码登录 | — | 官方通道没有"登录"这一步 |

## 5. 为什么默认值不影响老用户

- **全新安装**（还没有 `config.json`，读模板）→ 默认 `official`；
- **已有 `config.json` 但没有 `channel` 键**（升级上来的老配置）→ 继续 `napcat`，
  启动日志会说明"按旧配置兼容模式"。

默认值只作用于新装，不改写已装用户的出口 —— 否则升级当天就会出现
"机器人一条都不收，而它其实只是没配凭据"这种最难查的静默失效。

想强制指定（测试或多实例）：环境变量 `QQBOT_CHANNEL=official|napcat`。

## 6. 排错顺序

机器人在线但不回话时，按这个顺序看，不要先怀疑代码：

1. **面板「运行 → 切换协议端 → 接入通道」那格**：是"待配置 / 连接中 / 在线 / 鉴权失败 / 停摆"哪一种；
2. **有没有收到事件**：收到 = 平台在推；没收到先查应用权限与机器人是否在群里；
3. **群有没有绑定 / 在白名单**：未绑定的群键是 openid，白名单里没有它就会被判"群不在白名单"；
4. **是不是只有 @ 才回**：那是群主没开「接收所有消息」，不是故障；
5. **发送被拒的码**：`40034128` 被动窗口/次数超了、`40054003` 机器人不在群里、
   `40054010` 这条不允许带链接、`40034100/40034105` 主动消息没配额或没权限、
   `40054016`/`304018` 网关没连上；
6. **WS 4914 / 4915**：机器人被下架或封禁。这是平台单方面决定，重试没有意义，
   面板会停手并显示原因。

## 7. 官方通道的风险，说在前面

- 官方能力与频控**会变动**，且文档与真实推送行为存在已记录的出入；本文件的接口事实
  核对日期是 2026-11-06，引用前请复测。
- 官方机器人身份自带「机器人」标签，这是这条通道的产品前提，不是缺陷。
- AppSecret **不能重置**（官方 FAQ）：泄露只能换应用。所以它不进日志、不进面板、不进仓库。
- 平台可以单方面下架/封禁且暂无申诉通道。

## 8. 这条通道靠哪些门守着（2026-11-06）

| 门 | 命令 | 盯什么 |
|---|---|---|
| 契约段 §190（九条） | `NODE_OPTIONS= node scripts/check-wb.mjs` | 默认只作用新装、被动 5/4 与窗口按本机到达、翻译+合并+持久去重且消息出口唯一、不支持能力明确失败、地址钉死与凭据不回显、openid 与人工绑定单一真值、面板接线与写操作分类、启动链按通道、回归在 verify 里 |
| 离线 + 端到端 | `NODE_OPTIONS= node test/check-official.mjs` | 纯函数逐条 + 本机假官方网关（真 WS、真 HTTP）：READY→selfId、identify token 格式与订阅位、AT+全量合成一条、重复推送丢弃、被动 `msg_seq` 递增、发图两步、op7 重连后 resume、失败码归一、AppSecret 只出现在取 token 那一条请求 |
| 真渲染 | `NODE_OPTIONS= node test/panel-dom.mjs` | 「接入通道（官方）」那一段：密码框不回显、未配置/要重启两格跟着状态出现与消失、待绑定行来自机器人快照、点绑定落行、同群号抢绑被拒、设主人、解绑走确认卡 |
| 定向变异 | `QQBOT_MUTATE_WORK=/tmp/x NODE_OPTIONS= node scripts/mutate.mjs test/mutations/official-channel-2026-11-06.mjs` | M1–M17 逐条把防线打红（M5/M6 走新的 `official` 层，因为静态判据钉不住接缝），C1 是**对照组**：只改文案措辞必须 NOT-BLOCKED，否则说明判据在匹配"任何改动" |

两条纪律值得单独说：

- **`test/sandbox.sh` 显式把通道钉成 `napcat`。** 沙箱配置来自 `config.example.json`，
  而那份的默认已经是 official；沙箱那 200 多条断言全是围着 OneBot 那条线写的，
  不钉的话"本机有 config.json（兼容 NapCat）"和"CI 干净检出（示例 ⇒ official）"
  会验到两条不同的线。要反过来验官方：`QQBOT_CHANNEL=official bash test/sandbox.sh --run`。
- **P7 的真机联网验收还没做，也不该被上面任何绿灯代替。**
  离线测试断言的是"我们发出去什么形状"，不是"平台今天答不答"。
  真机矩阵需要：一个官方机器人应用的 AppID/AppSecret、一个测试群，
  且群主愿意开「接收所有消息」与「允许主动发言」。缺任何一样，本节就是空白。
