## 0 · 一句话结论

Bencho 那套代码真正值钱的**不是代码，是注释的写法**：
每个参数都写清「改成多少、为什么、实测多少」。它把调参从玄学变成**可复算的东西**。

例：它把阻尼从 220/20 改成 170/21.5，注释写的是
「默认 ζ 是 0.71，穿越很快但末尾有可见的啪一下 —— 一个开关把自己甩到另一侧。
170/21.5 是 ζ 0.87：仍然带着一点弹性暗示，而那点暗示就是全部。」

我们用同一套公式算出来：ζ=0.711 过冲 4.2% / ζ=0.869 过冲 0.4%。**对得上。**
这就是「注释可复算」的含义 —— 别人能验，不是只能信。

## 1 · 六条判据

### 判据① 一个位置，两种写法

位置存成**一个对象**（本项目是 `motionValue`），不是组件 state：

- 拖拽时手指直接 `set()` —— 硬写、无缓动、每帧跟手；
- 松手时 `animate()` 接管 —— 弹簧收敛。

两者写的是**同一个格子**，谁在写都不会通知对方，也**不触发重渲染**。

> ⚠️ 位置若是组件 state（哪怕是 ref 之外的 `useState`），拖拽必然重渲染，手感立刻垮。
> 这是本条唯一的硬要求，其余都是推论。

### 判据② 拖尾是弹簧跟随，不是延迟

后面拖一团的视觉，可以用两种底层机制实现，**体感天差地别**：

| | 机制 | 快甩时 |
|---|---|---|
| ✗ | 和主块**同一个目标** + `transition-delay` | 迟一步出发，落到主块早已离开的地方 → **脱队** |
| ✓ | **弹簧追着主块此刻的值** | 永远在追当前位置 → 拉伸量恰好等于主块此刻的速度 |

**实测（Chromium 逐帧采样，同一次甩动）**：

| 实现 | 峰值间距 | 形态 |
|---|---|---|
| 延迟 | **24.3px** | 超过液滴直径 36px 的一半 → 两团**完全脱开** |
| 弹簧跟随 | **12.7px** | 始终重叠 → goo 能拉出细颈，读作**一个**液滴 |

> **硬约束：两团必须始终重叠。** 跨过真实间隙的 goo 桥会细到撑不住，滤镜直接断成两团。
> `24.3 > 36/2` 就是断掉的数学证明。
> 实验室页有「定格在最大间距」按钮 —— 动画只有 300ms，**任何截图都只能抓到静止态**，
> 所以让读者手动定格，差异静止下来反而更好看清。

### 判据③ 拉伸要面积守恒

液滴沿运动方向拉长（`scaleX`）、垂直方向压扁（`scaleY`），且
**`scaleY = 1 / scaleX`** —— 乘积恒为 1。

> 不守恒的后果：横向拉长 1.4 倍**同时**保持高度 ⇒ 面积大了 1.4 倍，
> 视觉上是「它鼓起来了 / 变胖了」，而不是「它被抻长了」。**一眼假。**

### 判据④ goo滤镜层上只有不透明色块

`feGaussianBlur` + `feColorMatrix` 对 **alpha 做阈值**。所以：

- 半透明填充（`opacity` / `rgba`）经过它 = **整个形状消失**；
- 抗锯齿的**文字**会被同一道阈值吃掉边。

于是必须**两层**：

```
.goo-layer   带 filter  →  只有不透明色块，负责「融」
.ink-layer  不带 filter →  文字 / 描边 / 命中区，架在上面
```

两层**几何完全一致**，所以描边写在 ink 层上就**免费描出了下面那团的轮廓**。

> **排错**：goo 效果突然不工作，九成是有人给色块加了 `opacity`。
> 要调色就`color-mix(in srgb, var(--c-text) 19%, var(--c-sunken))`——
> **混出那个颜色，而不是调透明度**。

> **排错**：液滴跑到轨道外 / 居中跳到中间 ⇒ 忘了 `left: 0`。
> 这些是 inline 元素，`left:auto` 时静态位置由行盒决定，而按钮会把文本居中。

### 判据⑤ transform 上永远不加 CSS transition

每帧写一次 `transform` + CSS 过渡 = **对每一帧重新插值**。
最后看到的是那条缓动曲线，**弹簧被彻底旁路**。

只有 `background` 这类「没有弹簧在管」的属性才过渡。

> Bencho 踩过的另一个同源坑：hover 缩放原本走 CSS `scale` 属性，而 `scale` 比 `transform`
> **先**应用 —— 于是 `scale:1.035` 先缩了坐标系，`translateX(51px)` 再在缩放后的空间里走，
> 51 变成 52.8，滑块在**开态**明显偏出轨道（关态偏移 5px 只差 0.18px，肉眼根本看不出来）。
> **正确做法：把缩放乘进 `scaleX`/`scaleY`。**
> 这条的一般形式：**多个派生值必须乘进同一个 transform，不能各写一条 CSS 属性。**

### 判据⑥ 拨盘 = 物理量，不是曲线

`Bounce` 是**阻尼**、`Speed` 是**刚度** —— 两个旋钮都是**同一个弹簧的属性**，
而不是两条不同的缓动曲线。所以 UI 上**不该给用户「曲线」选项**。

| 参数 | 值 | 决定什么 | 可调吗 |
|---|---|---|---|
| `stiffness` | `170 − (50−speed)×1.1` | 多快抵达 | ✅ 用户可调 |
| `damping` | `21.5`（ζ≈0.87） | 有没有回弹、手感软硬 | ❌ **写死** |
| `mass` | `0.9` | 惯性重量感 | ❌ 写死 |
| 速度→拉伸的除数 | `600` | 拉伸的可见程度 | ❌ 标定值 |
| 拉伸上限 | `0.4` | 留给 Stretch 旋钮的余量 | ❌ 标定值 |

**为什么阻尼写死**：从死板到活泼的整个范围，区别只在
「一个能用的控件」和「一个在表演的控件」之间。开关不该有回弹旋钮。
而 Speed 仍可调，因为「多快」是个真问题。

> **除数 600 是标定值，不是拍脑袋**。Bencho 注释写得很清楚：
> 44px 行程峰值约 150px/s，除以 1400 时峰值拉伸只有 **1.039** ——
> 算术上存在，**视觉上不可见**。除以 600 → 峰值约 1.09，才是「恰好能看出来的弹性」。

**三档阻尼的实测行为**（目标 100px，60fps）：

| | c | ζ | 过冲 | 到 95% |
|---|---|---|---|---|
| 欠阻尼 | 21.5 | 0.869 | 0.4% | 16 帧 |
| 临界 | 2√(km) = 24.7 | 1.000 | 0% | 20 帧 |
| 过阻尼 | 30 | 1.213 | 0% | 27 帧 |

## 2 · 三个实现级判据（踩过的坑，别再踩）

###① `releasePointerCapture` 会抛，而抛在错误的位置

一个开关的 `held` 状态如果永远为 true，**液滴就停在拖拽处再也不落位**，
表现是"开关卡住了"。根因却是一次未捕获的异常：

```js
// pointerup 处理器
try { track.releasePointerCapture(e.pointerId); } catch {}   // 必须在最前
if (!moved) setOn(!on);   // 抛在这里之前 ⇒ setOn 永不执行
setHeld(false);
```

`releasePointerCapture` 在「指针从未被成功捕获」时**必抛** ——
而捕获本身也可能失败（`down` 里的 `setPointerCapture` 同样要 try/catch，
因为指针已经不在了：真实场景指针已离开页面，测试里是合成事件）。

> **一般化的说法**：一个"清理动作"如果会抛，它就必须排在**状态恢复之前**，
> 否则一次异常 = 状态永久卡死，且症状与原因隔着好几层。

### ② 抓取偏移在第一次 move 取，不在 down 取

Bencho 修掉的原bug：`down` 里就决定偏移，命中滑块外时取"半颗滑块宽"，
意图是"液滴主动靠到手指下"。但 `x.set()` 是**无弹簧的硬写** ——
首次 `pointermove` 一步之内把液滴挪 46px（**瞬移**）。

改成第一次 `move` 取偏移：那次 move 位移为 0，之后每步只跟增量。
于是**这个控件上任何一处按下都不可能跳**。

> 代价：离滑块较远时按下拖拽，液滴不再主动靠过来，而是按位移量移动。
> 在 92px 的轨道上你永远离滑块不远，而 46px 的瞬移是更糟的那个。

### ③ 静止判据要**位移和速度都**满足

只看位移会在**过冲顶点**误判为静止（此时位移还很大但速度为 0），
动画会在半路永久停住。本项目阈值：`|Δx| < 0.01px` **且** `|v| < 0.05px·s⁻¹`。

## 3 · 引擎约定（`panel/next/motion.js`）

零依赖，**属性与 framer-motion 对齐**（同名、同手感），
所以从 Bencho 抄来的配方可以**原样**搬进本项目。

| API | 用途 |
|---|---|
| `Motion.motionValue(v)` | 一个可写位置；`.get() .set() .jump() .velocity() .on()` |
| `Motion.animate(mv, target, cfg)` | 弹簧收敛；返回带 `.stop()` 的句柄 |
| `Motion.springStep(state, target, cfg, dt)` | **单帧推进**，给"自己控制时钟"的组件用 |
| `Motion.transform(mv, fn)` | 派生值 |
| `Motion.toTransform(pairs)` | 组合成 CSS transform 字符串 |
| `Motion.areaPreservingScaleX(sx)` | 面积守恒的配对缩放 |
| `Motion.localX(el, clientX)` | 客户端坐标 → 元素自身坐标（**组件被缩放时必做**） |
| `Motion.reducedMotion()` | 系统是否要求减弱动效 |

### 三条不许破的约定

**① 一份语义，一份实现。**
弹簧公式**只在 `motion.js` 里存在一次**（`springStep`）。
需要自己控制时钟的组件**调它**，绝不在组件里再抄一份 ——
抄一份就多一个能悄悄对不上的机会，且两个副本会各自漂移。
（本项目已有的红线：一份语义一份实现，已在别处栽过十几次。）

**② 一个 rAF 驱动全部。**
最常见的错是"每个动画各起一个 `requestAnimationFrame`"：
30 个动画 = 30 次调度/帧，且**回调顺序不确定** → 同一帧里父子动画先后随机漂移（看起来就是穿模）。
`motion.js` 用单个 tick + 订阅集合，**一帧内后注册的后执行**（后启动的动画时间戳更新，位移更接近真实时间）。

**③ 减弱动效是尊重，不是可选项。**
`prefers-reduced-motion: reduce` 时**直接落位、不注册任何帧循环**。
用 `set` 而不是 `jump` 落位 —— `set` 会正确清掉速度，下一帧的形变不会莫名拉伸一下。

## 4 · 怎么接进产品页

三行。零构建、零依赖、零服务。

| 位置 | 加什么 | 注意 |
|---|---|---|
| `index.html` 的 `<head>` | `<link rel="stylesheet" href="liquid-toggle.css">` | 放在 `style.css` **之后** |
| `<body>` 末尾 | `<script src="motion.js">` 然后 `<script src="liquid-toggle.js">` | ⚠️ **顺序不能反** |
| `app.js` 渲染处 | `LiquidToggle.create({ speed, stretch, on, onChange })` | 存句柄；**元素移除时必须 `destroy()`**，否则 rAF 泄漏 |

> 资产名已在 `panel/lib/next-page.js` 的 `NEXT_ASSETS` 登记，接入时**不需要再改那张表**。

### 用在什么上、不用在什么上

液态 goo 适合「**少量、关键、状态明确**」的控件：总开关、模式切换、启用/停用。

**不要整页都液体。** 控制台的主线是`style.css` 开头写的那条
「安静的仪表盘」：中性冷灰底 + 单色强调，靠**层级与留白**分区，不靠装饰。
密集中文界面里满屏液态会削弱可读性 —— 动效只用于**状态变化**，不做进入动画。

### 核心：渐进增强，不是替换

`paintPage()` 用 `$id('page').innerHTML = html` **整页重建**（3 秒轮询一次），
所以任何挂上去的 DOM 都会被销毁。**因此**：

- **原生 `<input type=checkbox>` 是唯一事实源** —— change 绑定、被读值的都是它；
- 液态层是**纯装饰**，`pointer-events: none` 让点击**穿透**给原生 input；
- 由 `onPageShown → mountLiquidSwitches()` 重挂（**幂等**，重挂前先 `destroy()`）。

三个好处：① 退回原生只需 `LIQUID_ON = false`，**功能一行不受影响**；
② 装饰层出任何问题都**不影响功能**（最坏是看不见装饰）；
③ rAF 不泄漏（实测重渲染 5 次后 `Motion.activeCount() === 0`）。

### 为此新增的 API：`sync()` 而不是 `set()`

```js
liquid.set(v)   // 当作"用户操作" —— 会触发 onChange
liquid.sync(v)  // 当作"镜像/同步" —— 不触发 onChange★ 装饰层用这个
```

⚠️ 装饰层用 `set()` 会形成「读状态 → 写配置 → 再读状态」的**回环**。
不要靠 `setOn` 里的 `if (next === on) return` 早退来兜 —— 语义上它就是一次用户操作。

### 尺寸：档位表而不是常量

`LiquidToggle.SIZES`：`card`（92×46 / blur 7）与 `mini`（40×22 / blur 2.6）。

⚠️ 早期是模块级 `TRACK / THUMB / PAD` 常量，CSS 把尺寸改小之后，
**JS 的旅行距离与 CSS 脱节**（液滴走 46px 却按 18px 算 ⇒ 滑块飞出轨道）。
改成档位表后几何与滤镜半径**同一个来源**。

⚠️ **模糊半径必须跟着尺寸走**：小液滴糊过之后峰值 alpha 会掉，
掉到阈值以下就**整个消失**。所以滤镜**按 `stdDeviation` 分档缓存**（`gooCache`）——
共用一个会在换档时静默失效。

### 配色必须跟随原生（这条是可用性问题，不是审美）

原版用「ink 反转」：**开 = 深色轨道**。但控制台原生开关是**开 = 蓝**。
两套语义**相反** ⇒ 页面上「哪个是开的」读不出来（液态那两个偏灰、原生那个偏蓝）。

`.liq-toggle.mini` 因此**跟随原生**（开 = `--c-accent`、关 = `--c-line-strong`），
代价是失去"黑白反转"那种液态特有的对比。**能用比"好看但读不懂"重要。**

### ⚠️ 踩过的坑：CSS 不能写成 `<script>`

```html
<!-- ✗ 错：浏览器会把 CSS 内容当 JavaScript 解析 -->
<script src="./liquid-toggle.css" rel="stylesheet"></script>
<!-- ✓ 对 -->
<link rel="stylesheet" href="./liquid-toggle.css">
```

症状是 `SyntaxError: Unexpected token '.'`（`.sw {` 里的 `.`）。
⚠️ **极具欺骗性**：CSS 一样不生效（根本没加载成功），而报错发生在**解析期**，
看起来像"脚本坏了"，实际只是标签写错。
⚠️ **`check-wb` 抓不到**（它只看文件在不在，不执行 JS）——
**只有 `panel/next/verify.mjs`（真浏览器跑 32 个页面）能抓到**。
这是「回归全绿 ≠ 改动落地」的又一例。

## 5 · 验证方式（别只看它动起来）

| 想验什么 | 怎么验 |
|---|---|
| 引擎算得对不对 | `Motion.springStep` 纯函数，Node 里直接跑；三档 ζ 的过冲/收敛数应当与注释一致 |
| goo 有没有生效 | **截图看像素**。`motion.js` 里的变换能把两个 blob 的实际几何和间距打出来 |
| 拖尾是否真的重叠 | 逐帧采样主/尾间距，取峰值。本项目实测 24.3 vs 12.7 |
| 面积守恒 | 拉伸后读 `getBoundingClientRect()`，核对 `w×h ≈ 36²` |
| 键盘与无障碍 | `role="switch"` + `aria-checked` + 空格/Enter 都能切|
| 速度 → 拉伸的除数 | 改`VELOCITY_DIVISOR`，峰值拉伸应约 `1 + 除数⁻¹×速度` |
| **这个动效属于四来源里的哪一条** | 答不出就删（§6.1）。**这是最便宜也最有效的一条检查** |
| **S2 准入条件** | 三条逐条问：二值/有序？用户反复拨？位移承载语义？（§6.4） |
| **三档强度有没有混用** | 位置落在 §8.1 矩阵的允许格里；S2 出现在密集列表里 = 违规 |
| **降级路径** | 开 `prefers-reduced-motion` 跑一遍；`Motion.activeCount()` 应归零（无帧泄漏） |

> **一个必须记住的坑**：`var frame = document.createElement(...)` 与
> `function frame(now) {...}` **同名**时，函数声明胜出，DOM 变量被覆盖成函数。
> 表现是「DOM 完全正确、rAF 只跑一帧、`rAF 参数不是 Function`」。
> 本项目真的栽过这一次——**同名遮蔽在JS 里不报错，只是让变量变成另一种东西**。

## 6 · 「灵动」的判据：生动 = 状态被看见

> 2026-10-03 扩充。`style.css` 写的是「动效只用于**状态变化**，不做进入动画」——
> 但**什么算"状态变化"、什么算装饰**，此前全仓没有一句话说清。
> 后果是：判据不在，**没人敢用** `motion.js`（能力写完放了两周，产品页零接入）。
> 本节就是把那条缺失的边界补上。

### 6.0 一句话

**生动 = 状态被看见，不是元素在动。**

支撑它的实测：`Motion.animate` 的默认参数 `stiffness 170 / damping 26 / mass 1` 算出来

```
ω₀ = √170 = 13.038        ζ = 26 / (2·√170) = 0.9970        1/(ζω₀) = 76.9ms
```

**默认档本身就是临界阻尼、不过冲** —— 也就是说"生动"**不可能**来自把弹簧调软
（那只会得到"一个在表演的控件"，见判据⑥）。它只能来自**把状态画出来**。

### 6.1 生动的四个合法来源

任何一个动效，必须能指出它属于下面哪一条。**指不出的就是装饰，删。**

| # | 来源 | 它回答的问题 | 本项目已有的实例 |
|---|---|---|---|
| 1 | **状态被画出来** | 这个值现在是什么 | `statusGrid`（坏的那格自己变红，不用读数字）· `emotionState` |
| 2 | **连续映射** | 它在序列里的哪一格 | `ticks`（高度真实映射顺序，而不是"选中态"跳变） |
| 3 | **物理感** | 它从哪来、到哪去 | `.nav1` 指示器：弹簧位移 + 速度→形变 + `areaPreservingScaleX` 面积守恒 |
| 4 | **时间感** | 它在变好还是变坏 | 日志单调游标 + `reset` 协议；看趋势而不是瞬时值 |

⚠️ **四条里只有第 3 条需要 `motion.js`**。第 1、2 条 CSS 就能做，第 4 条是数据层的事。
所以"要不要引动效引擎"不该是默认问题 —— 大多数"让界面活起来"的需求，
答案在**数据层**（把值下发出来）和**映射层**（把值接到几何上），不在动画层。

### 6.2 五条"不该动"的判据

命中任意一条，这一处**不许有任何位移或缩放**：

1. **密集中文列表** —— 一屏 20 行以上时，任何逐行位移都会让阅读位置丢失。
2. **长期停留的配置表单** —— 用户在这里对着键盘思考，动的东西是干扰。
3. **每轮询重绘的区域**（本项目 3 秒一轮）—— 动效会被重绘打断，表现为"闪一下"。
4. **没有状态变化的纯展示** —— 数据没变却动了 = 纯粹的谎言。
5. **任何"进场动画"** —— 每次进页面都演一遍，第三次就烦。`style.css` 明令禁止的就是这条。

### 6.3 三档强度 S0 / S1 / S2

| 档 | 名字 | 用什么实现 | 允许出现在 | 现有实例 |
|---|---|---|---|---|
| **S0** | 静默 | 无（连 hover 都没有） | 密集列表、配置表单、每轮询重绘区 | 表格行、表单控件 |
| **S1** | 状态 | CSS `transition: … var(--dur) var(--ease)` | **默认档**：按钮 / 开关 / tab / 卡片 | `.btn`、`.sub[aria-selected]` 的底色与描边 |
| **S2** | 物理 | `window.Motion`（弹簧 + 派生变换） | **少量、关键、状态明确**的控件 | `.nav1` 指示器 |

**默认 S1。** 用 S0 要说明理由；用 S2 要过准入条件。

### 6.4 S2 的准入条件（三条**必须同时成立**）

1. **状态是二值或有序的** —— 开关（开/关）、档位（1–7 档）、选中项（第几项）。
   ⚠️ "一个连续变化的数字"**不算**：它该走 S1 的宽度过渡，或 §6.1 第 2 类的高度映射。
2. **用户会反复拨它** —— 总开关、导航、模式切换。**一次性按钮永远不配 S2。**
3. **它的位移承载语义** —— 指示器移到哪 = 现在选中谁。移了却不表达任何东西 = 装饰。

### 6.5 「该动吗」四问

照顺序问，任一条答"否"就停在那一档：

```
Q1 这里有没有"状态变化"？────────────────否──▶ S0（不是"少动"，是不动）
 │是
Q2 用户是不是在等一个结果？──────────────是──▶ S1 + 遮罩/toast（走 §7.1 的模板）
 │否
Q3 状态是二值/有序的，且用户会反复拨它？──否──▶ S1
 │是
Q4 位移本身承载语义吗？──────────────────否──▶ S1
 │是
 └─▶ S2（用 window.Motion，不许新写 rAF）
```

## 7 · 交互流程编排

> 判据管"动不动"，本节管"**先后顺序**"。
> 本项目写操作有一条贯穿的取向：**不做假成功**（`docs/FRONTEND-V2.md` §3.4）。
> 三种模板就是它的落地形状 —— **先认领模板，再写代码**。

### 7.1 三种编排模板

**A · 即时报文**（点一下就写，结果读回来）

```
点击 → disabled + 全屏遮罩(带文案) → POST → 回读 /api/state → toast 三色 → 撤遮罩
```

- 遮罩**必须带文案**（"正在切换模型，可能要几十秒"）。无文案的转圈会被读成"卡死了"。
- toast 三色语义固定：`ok` 已保存并生效 · `warn` 保存了但有副作用（需重启 / 能力被自动关掉）·
  `bad` 失败且**原文照抄后端错误**（不许改写成"操作失败"——那会把可诊断的信息丢掉）。

**B · 草稿聚合**（改一堆，提交一次）

```
改动 → 进草稿(不写盘) → 保存条计数 +1 → [保存并生效] → POST 一次 → 回读 → toast
```

- 计数必须统计「**被用户真正动过的路径数**」。本项目真栽过：拿"草稿里有几个键"当计数 ⇒
  光**打开**一页就显示「有 5 处改动还没保存」，而且"有草稿就不重画"的轮询保护会因此**永久停更**。
- 「丢弃改动」必须真的把保存条**撤掉**，判据取算出来的 `display`（见 §8.4）。

**C · 命令下发**（我只是把命令写下去了）

```
点击 → POST(只写命令) → toast 只说"已下发，等机器人取走" → 从 /api/state 回读判完成
```

- ⚠️ **不许说"已完成"**。命令通道的另一端是另一个进程，它可能还没取走。
- 判"换好了"要看**状态**（例：面板重启后 `pid` 变了），不是"接口返回 200"。

### 7.2 轮询下的编排（本项目 3 秒一轮）

| 纪律 | 为什么（都是踩出来的） |
|---|---|
| **重画指纹必须覆盖整个视图** | 只比 `totals` ⇒ 页面永不更新且**一句报错都没有** |
| **用户正在输入就不重画** | 否则光标被吞 |
| **单调游标 + `reset` 协议** | 日志环形缓冲封顶 600 行后 `total` 恒为 600 ⇒ 游标到 600 后 `slice(600)` 永远为空，**面板永久冻结**。修法：后端 `total = dropped + len` **单调递增**；游标落后太多时下发 `reset`，前端**先清空再追平**。二者缺一不可 |

### 7.3 动效与整页重建的冲突（三种解法，选一种，别即兴）

`paintPage()` 用 `innerHTML` 整页重建 ⇒ **任何挂上去的 DOM 都会被销毁**。
S2 控件与重建共存只有三条路：

| 解法 | 做法 | 代价 |
|---|---|---|
| **a · 事实源与装饰层分离** | 原生控件是唯一事实源；动效层 `pointer-events:none` 纯装饰；由 `onPageShown` **幂等重挂**（重挂前先 `destroy()`） | 要维护 `destroy/mount` 成对 |
| **b · 承载动效的元素不参与重建** | 指示器是 `index.html` 里的**静态元素**，渲染器只摘/插选项 | 渲染器要知道哪块是静态的 |
| **c · 输入指纹跳过无变化的重绘** | 用 `data-k` / 值指纹守卫，没变就不碰 DOM | 指纹漏字段 = 永不更新 |

⚠️ **三者关系不是三选一的并列**：b 是**前提**（静态元素本就不参与重建）、
c 决定**要不要重绘**、a 管**重绘之后怎么把装饰挂回去**。
真接一个 S2 控件时，通常是 **b + c + a** 一起用。

## 8 · 适配不同场景（范围：控制台 `panel/next/`）

### 8.1 三轴适配矩阵

| 信息密度 ＼ 强度 | S0 静默 | S1 状态 | S2 物理 |
|---|---|---|---|
| **密**（列表 / 表格 / 日志） | ✅ 默认 | ⚠️ 只允许底色与描边，**不许位移** | ❌ |
| **中**（卡片 / 表单） | ✅ | ✅ 默认 | ⚠️ 仅限"开关"类 |
| **疏**（导航 / 关键指标） | ⚠️ | ✅ | ✅ 主战场 |

**输入方式**：`@media (pointer: coarse)` 下**触摸目标补到 44px**，
且 S2 的拖拽要改成"点按即切" —— 手指按住拖一个 40px 的滑块，误触率高于收益。

### 8.2 断点策略（沿用现有，不新增档位）

| 断点 | 变化 |
|---|---|
| ≤1180px | 卡片栅格**塌成一列** |
| ≤900px | 灵动岛外留白降到 `--s4` |
| ≤720px | 岛高 48 / 选项 36、字号降到 `--t-sm` |
| `pointer: coarse` | 岛高 60 / 选项 44 |

⚠️ 吸顶偏移**由令牌推导**（`--h-topbar` + `--h-nav1` + `--h-nav-pad`×2），**不写死**。
写死的表现是"二级导航上沿被岛压掉一条"，而**两级导航各自看起来都正常** —— 极难归因。

### 8.3 同一语义、不同密度的不同呈现（先例：档位）

`ticks` 与 `seg` **共用同一套数据契约**（同一个 `options`、同一个 `valueOf`/`setValue`），
差别**只在呈现**：

- 宽屏 / 稀疏 → `ticks`（高度真实映射顺序，顺序**看得见**）
- 密集 / 窄屏 → `seg`（分段单选）
- **少于 3 档 → 自动退回 `seg`**（2 档时高度差表达不了顺序，白占一行高度与一套指针逻辑）

**这就是"适配"的正确形状**：不是给同一控件写两套代码，
而是**一份数据契约、多个渲染器**。写两套代码的版本一定会漂移。

### 8.4 降级路径（每一条都要有，不是可选项）

| 场景 | 降级为 |
|---|---|
| `prefers-reduced-motion: reduce` | `Motion.animate` 直接落位、不注册帧循环；CSS 过渡时长归零 |
| 控件不支持某能力 | **不出现**（不是灰掉）—— 灰掉的控件会让人以为"点一下也许就行" |
| 后端没数据 | 给**人话**（"那个包还没被用到过"），**不画红** —— 没数据是正常状态 |
| 没拿到 token | 页面明说；**读仍正常** |
| 触摸设备 | 目标补到 44px；S2 拖拽改成点按 |

⚠️ **判"可见"要取算出来的 `display`，不是 `hidden` 属性。**
本项目真栽过：`#busy` / `#modal` / `.savebar` 自己声明了 `display:grid/flex`，
压过 UA 的 `[hidden]{display:none}` ⇒ 整页永远蒙一层灰 + 中间浮一个空弹窗框 + 底部常驻保存条，
而 DOM 里这三个元素的 `hidden` **全都是 true**、`node --check` 与 jsdom 断言**全绿**。
判据必须写成 `getComputedStyle(el).display !== 'none'`。
