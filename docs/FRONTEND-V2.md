## 3. 整体结构与布局

### 3.1 五个横向区域（自上而下）

```
┌─ 顶栏 (sticky) ────────────────────────────────────────────────────────────┐
│ 品牌        │ 状态胶囊：已连接/演示 · 机器人 · 容器 · 本机模型 · 内存 │ 配色 · 一键启动 · 结束运行 │
├─ 告警条（按需出现，平时不占位置）──────────────────────────────────────────┤
│ 演示模式 / 没拿到 token / 面板跑着旧代码 / 内存很紧 / 实例锁被占            │
├─ 一级导航 (sticky) 8 个功能域 ─────────────────────────────────────────────┤
│ 运行5 · 大脑4 · 人格5 · 记忆与知识4 · 情绪与世界4 · 发言与时机4 · 扩展2 · 系统3 │
├─ 二级导航 (sticky) 玻璃只包当前域内的页（B30：fit-content + 右缘斜角切割）─┤

│ 页面标题 + 一句话说明 + 面包屑                                             │
│ 卡片（span 4 / 6 / 8 / 12；窄屏自动塌成一列）                              │
└─ 页脚：规模统计 ───────────────────────────────────────────────────────────┘
   常驻浮层：草稿保存条（有改动才出现）· toast（右下）· 遮罩（动作中）· 弹窗（确认清单）
```

**为什么是两级而不是一级**：31 个页面平铺没人找得到；而"域"这一层正好对应

它什么心情 / 它什么时候说话 / 它装了什么东西 / 系统本身），而不是代码模块。

### 3.2 页面间的组织关系（三条关系，不是三份拷贝）

1. **同一份配置只在一处摆控件**。`allowProactive`（主动发言总闸）只出现在
   「大脑/思考与能力」；`features.*`（三个模型能力）同上；`requireAtInGroup` 只在
   「发言与时机/触发方式」。旧页面是"设置那边一份、工作台那边一份，靠镜像同步"——
   新页面**取消镜像**（一份数据一个控件位，没有第二处可漂）。
2. **相关但不相同的，用页内跳转说明串联**，而不是把控件搬过去。例：
   「运行/总览」的睡眠行写明"改作息在「发言与时机 → 睡眠作息」"。
3. **不可达的（没有后端支持）写成骨架块**，写明：数据在哪、缺的是哪一处接线、
   为什么这一版**不编数字**。这三块是：情绪状态、群友档案、节假日表。

### 3.4 交互的四种反馈（统一到这一层，控件只声明"我属于哪种"）

| 反馈 | 什么时候 | 长什么样 |
|---|---|---|
| **后果可见** | 任何写操作前后 | 底部保存条计数（草稿）／按钮 disabled + 全屏遮罩带文案（耗时动作） |
| **结果如实** | 每次写操作回来 | toast 三色：`ok`（已保存并生效）/ `warn`（保存了但能力被自动关掉、或需要重启）/ `bad`（失败，原文照抄后端错误） |
| **不做假成功** | 命令通道这类"我只是把命令写下去了"的动作 | toast 只说"已下发，等机器人取走"，**不说"已完成"**；结果从 `/api/state` 读回来 |
| **过期也说得清** | 记忆复核、撤销这类"另一个窗口刚改过"的场景 | 后端 404 与 400 **分开提示**（"这条不在了" vs "参数写错"） |

### 3.5 怎么进入（三个入口，都指向同一个页面）

| 入口 | 位置 | 行为 |
|---|---|---|
| 控制台图标 | Dock / 访达里的 `QQ-BOT-CONTROL.app` | 开 **`http://127.0.0.1:8788/`** —— 这就是控制台，没有第二个可回落的目标 |
| 直接地址 | `http://127.0.0.1:8788/` | 手打或书签 |
| 老地址（兼容） | `http://127.0.0.1:8788/next/` | **302 → 根**（只为旧书签；别存这个） |

> ⚠️ 上面这张表是 2026-10-02「换主」之后的现状。本文 §3.5 更早的版本写的是"图标默认开 `/next/`、
> 探不到回落 `/`、旧页面顶栏有「新版界面 ↗」入口" —— 那三条**都已作废**（见文首的更正块）。

回退：新页面顶栏右侧有「旧界面」链接 → `/`。

**为什么是"面板自己发"而不是另起一个小服务**：面板**不发 CORS 头**。用另一个端口打开的新页面，
`/api/state` 会被浏览器拦掉、写请求也拿不到 token —— 只能退化成离线演示快照。
所以"能点进去"这件事**唯一正确的接法**就是让面板发它（`GET /next/`），
连带把 token 注入与同源一起解决。改任何**资产**（`schema.js` / `app.js` / `style.css` / `index.html`）
都**不用重启面板** —— 每次请求从磁盘读，刷新即可（与现役片段同一条纪律）。

### 3.6 长列表封顶（2026-10-04 · 会随数据一直长大的列表）

| 维度 | 约定 | 为什么 |
|---|---|---|
| 上限 | `app.js` 的 `LIST_CAP = 15`（`CHIP_CAP = 12` 给概览 chip） | 全站只有这两个数；渲染器**不许各自 `slice()`**，否则"上限是多少"变成 N 个互相不知道的数字 |
| 唯一实现 | `capRows(list, kind, rowFn)` / `capChips(items, chipFn)` | 超出时尾部出「展开剩下 N 条」；`kind` 是展开态的键，**必须稳定** |
| 展开态 | `S.extra.open[kind]` + 动作 `list.more` / `list.fold` | **纯 UI 状态**：不进配置、不落盘、不进"未保存改动"计数 —— 它活得过 3 秒重绘靠的正是这一点 |
| 展开态高度 | `--h-list: min(56vh, 520px)`（`.rows.scroll-y.capped`） | **只管展开态**；折叠态靠"只画前 N 条"变短，不靠滚动 |
| 已封顶（5 + 2） | 结构化记忆 · 手动记忆 · 历史存量 · 群友档案 · 额度情报 +「它记得什么」两组 chip | 共同点：**条目数随使用一直涨** |
| 未封顶 | 对话流（后端已有 120 行上限）· 会话 / 存档 / 审计（已是限高滚动窗）· 定时消息 / 节假日（量小且要编辑） | 各有别的上限，或不该藏条目 |
| 折叠块内容 | `.det > .rows` / `.det > .f` → `max-height: var(--h-list); overflow: auto` | 展开后也不撑长卡片；与上面的限高**共用同一个数** |
| **重绘保状态** | `app.js` `keepPageState` / `restorePageState` / `elPathOf` + `KEEP_SEL` | 接在 `paintPage` 两侧（采集在 `innerHTML =` **之前**、恢复在**之后**）。恢复 `details.open` · 容器 `scrollTop` · 整页 `scrollY`（**只在"被弹回顶部"时补**）。键 = 路径 + 页号；⚠️ `KEEP_SEL` **登记制**，新滚动容器要登记 |

> ⚠️ **为什么是"截断"而不是"容器里滚动"**：`paintPage()` 每 3 秒重建 `#page` ⇒
> 任何 `scrollTop` 都归零，"滚到一半弹回顶部"比"列表长"更难用。
>
> ⚠️ `rowFn(item, i)` 的 `i` 必须是**原数组下标**（切片**前**绑定）——
> 可编辑列表（手动记忆）靠它定位改哪一条，用切片下标会**静默改错行**。
>
> ⚠️ **本机制不修倾斜**：它修的是**长度**。卡片变矮之后，同样 1° 的边缘位移自己就回去了 ——
> `tilt.js` / `MAX_DEG` / `perspective` 一行未动（用户明确要求"不要动倾斜"）。

## 4. 怎么加、怎么删（这份东西能不能继续开发）

### 4.1 一次改动的全部成本

| 你想干的事 | 改哪里 | 会不会牵动别处 |
|---|---|---|
| 加/删一个页面 | `schema.js` 的某个 `subs[]` | 不会 |
| 加/删一张卡片 | 那个页面的 `cards[]` | 不会 |
| 加一个「存进 custom」的控件 | `ctrls[]` 里加一项 + `bind:'点号路径'` | 不会 |
| 加一个「立即生效」的控件 | 加 `save:(v,s)=>({url,body})` | 不会 |
| 改文案 | 就在 schema 里改 | 不会 |
| 加一种**新控件类型** | `app.js` 的 `RENDER` 表加一个函数 + 在 `schema.js` 的 `CTRL_KINDS` 里登记 | 只有这一处 |
| 改视觉 | `style.css` 顶部令牌 | 只有这一处 |
| 加一个新的**静态资产** | `panel/lib/next-page.js` 的 `NEXT_ASSETS` 加一行 | 只有这一处（契约会核"磁盘 vs 名单"两个方向） |

### 4.2 三条会自动报错的纪律（把"会漏"变成"会红"）

1. `RENDER` 表里没有的 `t` → 页面上**当场画红框**（不是静默跳过）。
2. 页面上每个 `data-a` 必须有处理者（`ACTIONS` 或 `INLINE_ACTIONS`）→ `console.error`，
   自检脚本把它算失败。**这一条是真抓到过东西的**：一个动作名没接线，按钮点了毫无反应。
3. 静态标记里出现 `data-act` 之类别的属性名 → 同样报错。**也是真抓到过的**：
   顶栏与保存条四个按钮因为属性名写成 `data-act` 而全部静默失效。

### 4.3 自检脚本里那两条"防假绿"的判据（值得保留成习惯）

- **判"可见"要取算出来的 `display`，不是 `hidden` 属性**。属性为 `true` 而元素照样铺满
  屏幕（组件的 `display:grid` 会压过 UA 的 `[hidden]`）——这正是本轮实测抓到的
  整页发虚的根因（见 §5③）。测试里我用 `getComputedStyle(...).display !== 'none'`。
- **等首屏数据要等 `/api/state` 回来，不能只等"卡片出来了"**。骨架先渲染、数据后到，
  那时读状态会把"在线"误判成"演示模式"。这不是产品的问题，是等待窗口开早了。

## 5. 数据链路上挖出的两处真实缺陷

> ⚠️ **这两处已在第二批（同日）修好**：根因是同一个 —— `custom` 的归一化是**白名单投影**，
> 而"带上它就行"这个判断写在了**白名单的错的一侧**。修法各一处，外加把契约从
> "面板有没有带上"升级成"**经 readCustom 往返之后仍在**"（`check-wb` §46 加强）。
> 下面保留原始的取证与复现，因为在修之前它们是**活的**，而且**回归全绿**。

### ① `custom.holidays` 存不住（**已修**）

**现象（修之前）**：面板上加/改节假日表，保存一次就没了。

**根因**：`custom` 的归一化是**白名单投影** —— `readCustom()` 返回的是显式对象字面量，
里面**没有 `holidays` 这一格**；而面板保存走 `cfg.custom = patchCustom(cfg.custom, body.custom)`，
于是**任何一次面板保存都会把这张表从 `config.json` 里抹掉**。

**证据**（直接调函数，不需要跑服务）：

```
$ node --input-type=module -e "const m=await import('./src/custom-config.js');
  const out=m.patchCustom({holidays:{'2026-10-01':'holiday'}},{safety:{antiFlood:true}});
  console.log('有 holidays 吗 →', 'holidays' in out);"
修之前：有 holidays 吗 → false
修之后：有 holidays 吗 → true   （{"2026-10-01":"holiday"}）
```

**额外的坑**：面板侧 `14-script.html` 的 `wbCollect` **确实**带上了 `holidays`，
注释还写着"不带的话保存一次就会清空" —— 那句判断是对的，但**补救写在了白名单的错的一侧**，
所以它一直没生效。机器人侧读的是 `cfg.custom.holidays`（`src/index.js` 里 `normalizeHolidays(c.holidays)`），
所以手改 `config.json` 能生效，**直到有人点一次保存**。

**修法（一处）**：`readCustom()` 的返回里加 `holidays: normalizeHolidays(c.holidays)`
（归一化交给 `holidays.js` —— 与 `browseLock` / `sleep` / `forwardExpand` / `crossSend` 同一条纪律）。

### ② 定时消息的「日期」「频次」两个维度实际失效（**已修**）

**现象（修之前）**：面板上给定时消息选「只工作日」或填某一天，看起来存下了，实际按"每天"跑。

**根因**：`scheduledItems()` 归一化后的形状是 `{id, at, text, enabled}` ——
**`date` 与 `on` 被静默剥掉**。而消费者两边都"优雅降级"成每天：

- `src/reminder.js` `matchesOn(on, dayKind)`：`REMINDER_ON.includes(undefined)` 为假 → `want='any'` → **恒真**；
- `src/reminder.js` `dueMsOf(entry)`：`entry.date` 为 undefined → 用今天 → **退化成每天这个点**。

**证据**：

```
$ node --input-type=module -e "const m=await import('./src/custom-config.js');
  const o=m.readCustom({custom:{trigger:{scheduled:[
    {id:'b',at:'07:00',text:'x',enabled:true,on:'workday',date:'2026-10-01'}]}}});
  console.log(JSON.stringify(o.trigger.scheduled));"
修之前：[{"id":"b","at":"07:00","text":"x","enabled":true}]        ← on 与 date 都没了
修之后：[{"id":"b","at":"07:00","text":"x","enabled":true,"date":"2026-10-01","on":"workday"}]
```

**为什么回归全绿**：`test/smoke.js` 里 D17 的用例（T297–T304）把 `dueMsOf({at,date})` 与
`matchesOn('workday', …)` **当纯函数直接喂字段**（第 7634 / 7703 行附近），
**从来没有一条用例走"经 readCustom 一遍"的路径**。这正是项目自己那条纪律的形状：
**"断言存在" ≠ "断言接线"**。

**修法（一处）**：`scheduledItems()` 的白名单里加回 `date`（ISO 形状校验）与 `on`（`REMINDER_ON` 闭集合），
且**认不出的日期留空而不回落成"每天"** —— 写错的日子静默变成每天，比不生效更难查
（与 `dueMsOf` 对"填了却认不出"返回 `null` 的取向一致）。

### ③ 新前端自己踩到并已修的**五**处（写在这里，因为它们是**同一类**）

| # | 缺陷 | 表现 | 为什么难发现 | 怎么堵住 |
|---|---|---|---|---|
| a | `#busy` / `#modal` / `.savebar` 自己声明了 `display:grid/flex`，**压过了 UA 的 `[hidden]{display:none}`** | 整页永远蒙一层灰 + 中间浮一个空弹窗框 + 底部永远挂保存条 | DOM 里这三个元素的 `hidden` **全都是 true**；`node --check`、jsdom 断言、`innerText` 全绿 | CSS 加一条 `[hidden]{display:none !important}`；自检加"截图前不允许有全屏遮罩"与"按计算样式判可见"两条 |
| b | 静态标记里写成 `data-act`，而事件处理器只认 `data-a` | 顶栏「一键启动/结束运行」与保存条「保存/丢弃」四个按钮**点了毫无反应** | 按钮长得完全正常；不点它永远发现不了 | 启动时静态扫描 `[data-act]` 并 `console.error`；自检断言其为 0 |
| c | `api()` 里写 `if (!S.online) throw`，而 `S.online` 初始为 `false` | **首屏那次 `GET /api/state` 被自己挡掉**，页面永远进不了在线态（表现为"一打开就是演示模式"，日志里一句错都没有） | 只有"读"被挡，页面看起来"能显示"（显示的是离线快照） | 守卫改成只管非 GET 方法；自检断言"拿到真实后端数据" |
| d | 用"草稿里有几个键"当改动计数 | 光**打开**一页就显示「有 5 处改动还没保存」；且"有草稿就不重画"的轮询保护会因此**永久停更** | 页面不报错，只是数字不对、数据不更新 | 改动计数改成"被用户真正动过的路径数"；自检断言"只浏览不产生未保存改动" |
| e | 入口地址写成 `/next`（末尾没斜杠） | **整页白屏**：HTML 正常到达，`./app.js` 与 `./style.css` 被解析成 `/app.js`、`/style.css` → 双双 404 | `curl /next` 是 **200**、`curl /next/app.js` 也是 **200** —— **两个都对**，坏的是它们之间的相对关系。而且这条只有在浏览器里跑才暴露 | 面板侧加 302 兜底 + 三处入口一律写 `/next/`；契约钉"必须有那次 302"；自检加**纯 HTTP 预检**：按 `new URL(ref, resp.url)`（浏览器同一套算法）逐条取一次 |

> 这五条的共同形状：**失败时不报错，只是"看起来不太对"**。所以本轮把每一条都变成了自检断言，
> 而不是靠"下次注意"。其中 (e) 是**第二轮接线时**踩到的 —— 它恰好说明"加了路由能通"
> 与"点了能进"是两件事：`curl` 两个地址各自 200，而用户看到的是白屏。

### ④ 接线之后，这件事不再靠"记得"

第二轮把"新页面能不能点进去"从**人工记得**变成了**闸门钉住**（`check-wb` 第 58 节，9 条子判据）：

| 判据 | 它挡的是哪种静默失败 |
|---|---|
| 资产名单与磁盘**双向一一对应** | 多一个文件（永远取不到）/ 少一个（声明了但 404） |
| 三道闸**喂反例真的全拒**（含 `README.md` / `verify.mjs`） | 白名单写松了 → 文档与自检脚本上了 HTTP 面，而页面照常工作 |
| 入口名只从 `NEXT_ENTRY` 来 | 路由里再写一遍 `'index.html'` → 改名时这里不会跟着改 |
| token **恰 1 处**且只给入口页 | 全量注入 → token 泄进 JS/CSS 资产（已实测资产里真实 token 出现 0 次） |
| 只 GET、且不在 `WRITE_ROUTES` / `READ_ONLY_POST` 里 | 把页面路由当接口分类 → 鉴权与审计语义被污染 |
| 与 `PARTS` **两个目录、两类清单**不渗透 | 把 `panel/next/` 并进 `PARTS` → 引入一次构建，破掉零构建 |
| 入口三处（launcher / 旧页面 / 新页面回退）**各恰 1 处** | 三处各写一遍然后漂移 → "点了没反应"或"回不去旧界面" |
| `/next` → `/next/` 的 **302 必须存在** | 少了它，手打 `/next` 或旧书签得到的是**白屏**（而两个 curl 都是 200） |
